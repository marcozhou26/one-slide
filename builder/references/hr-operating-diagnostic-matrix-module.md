# HR 运营诊断矩阵

## 用途

用于把 2–10 个 HR 服务、职级、职能、渠道或其他运营对象，按 2–6 个共同维度放入一张可复核矩阵。它取代固定的 `hr-level-function-matrix`、`hr-service-catalog` 和 `hr-ticket-intake`，不再强制 8×5、5 行或 5×4。

## 轻输入契约

- 用户可以提供自然语言、表格或完整结构化数据；Producer 先从现有材料推导行、列、单位和口径，不要求用户填写模块字段。
- 正式模块至少需要两个行对象、两个列维度、完整矩阵和一个可核验的数值列。只有会改变行列含义、单位或核心结论的缺失与冲突才阻断。
- 顶部指标为可选 0–3 项；缺少指标、颜色、强调项或结论时缩小对应区域，不追问。
- 行列数量超出页面可读范围、存在两个独立主图、或者来源只支持自由组合而不支持共同矩阵时，进入 `direct_composition`。

## 数据结构

- `rows`：2–10 个唯一 ID、来源化标签，可选来源化备注。
- `columns`：2–6 个唯一 ID、来源化标签、`primary` 定义。`primary.kind` 为 `number`、`percentage` 或 `text`；数值列可使用 `encoding=heatmap`，文字列只能使用 `encoding=text`。
- `secondary`：列级可选的第二个数值或百分比定义；存在时每个单元格都必须提供对应值。
- `matrix`：尺寸必须严格等于 `rows × columns`。每格提供 `primary`、可选 `secondary` 和 `source_ids`。
- `direction`：`neutral`、`higher_is_better` 或 `lower_is_better`，只控制有证据的强调方向，不改变数据。

## 正确性门禁

- 百分比必须在 0–100；数值必须为有限值，且默认不得为负。
- 行列 ID 唯一；矩阵尺寸、单元类型和 secondary 完整性必须一致。
- 热力只编码列内可比较的 primary 数值；不同单位之间不得共用色阶。
- 不从矩阵自动推断因果、责任或改进动作。洞察和结论必须有来源。
- 分类重标、人员流动或多阶段工单流向需要真实 From-To 数据，分别使用通用矩阵、`hr-from-to-mobility` 或 `sankey-flow`，不能塞入本模块。

## 输出

顶部为可选核心指标；主体为原生可编辑矩阵；右侧最多三条发现、原因或动作；底部为可选结论。行列根据输入数量动态分配，不使用固定业务标签。
