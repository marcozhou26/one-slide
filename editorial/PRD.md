# OneSlide Editorial Editor PRD

目标版本：OneSlide 1.4.0
产品定位：在 OneSlide Builder 生成一页原生可编辑 PowerPoint 后，以真实渲染为依据做一次克制、可回退、可验证的编辑式信息设计。

## 1. 用户任务

用户已经得到一页内容和技术链路正确的 PPT，但仍可能存在视觉主语不明确、解释远离证据、重复编码、层级平均、留白失衡或阅读路径生硬。用户不应再单独描述这些问题，也不需要学习另一个入口。

OneSlide 1.4 必须在同一入口内完成：

```text
内容与来源锁定 → Builder 初稿 → Editorial Editor → 完整回归 → 一页 PPTX
```

## 2. 核心价值契约

Editorial Editor 必须证明自己做的是编辑，而不是重新生成：

1. 先观察实际 PPTX、整页渲染和 layout，再提出修改；
2. 先列出真实整页渲染中肉眼可见的问题并按严重度排序，再选择一个最影响理解的问题；不得从“允许做什么”反推问题；
3. 一个候选可以包含服务同一假设的成组修改；
4. 修改后页面在至少一个核心维度明显优于初稿，且没有事实、关系、可读性或可编辑性回归；
5. 没有明确收益时保留初稿，允许 `NO_MATERIAL_EDIT`；
6. 用户仍只使用 `one-slide`，不需要单独调用编辑模块。
7. 页面区域和重复板块先于单个对象受到保护；局部改善不得以破坏区域平衡、板块内在秩序或制造无效空白为代价。

## 3. 目标读者与读者任务

- 目标用户：需要一页咨询型、分析型或决策型 PowerPoint 的业务人员、顾问、分析师和管理者；
- 最终读者：在会议或近距离审阅中，需要快速理解结论、证据和行动边界的人；
- 编辑任务：降低理解成本，强化结论与证据的对应关系，而不是增加视觉装饰。

## 4. 输入

本模块为 B 级文件生产模块。完整契约见 `references/input-contract.md`。

最小可运行输入：

- 恰好一页、可读取的 `.pptx`；
- OneSlide handoff 或可从页面稳定推导的中心结论与读者任务；
- 同一 PPTX 导出的整页 PNG 和 layout JSON，缺失时由模块生成；
- 输出目录，不覆盖源文件。

风格偏好、颜色偏好、修改数量和具体坐标不是用户必填项。

## 5. 编辑维度

单一事实来源见 `references/review-rubric.md`：

1. `visual_subject`：是否只有一个明确视觉主语；
2. `title_evidence`：标题是否由主证据直接支持；
3. `evidence_annotation`：解释是否贴近对应证据；
4. `semantic_emphasis`：颜色、字号和层级是否承担信息含义；
5. `reading_rhythm`：阅读顺序、留白、对齐和密度是否自然；
6. `information_contribution`：是否存在重复或无信息贡献对象。

## 6. 允许的修改

- 移动或调整已有原生对象尺寸；
- 调整字体大小、字重、对齐和文字颜色；
- 通过文字层级和位置弱化或强化已有信息；V1.4 暂不直接修改形状填充和边线；
- 把已有标签移动到对应证据附近；
- V1.4 不执行任何文字或形状删除；重复内容返回 Builder 重生成或阻断；
- V1.4 不直接删除无文字对象；发现旧页面装饰时优先由 Builder 重生成，无法安全重生成则阻断编辑；
- 对象层级、填充和边线操作待 Builder 提供可验证的对象语义角色后再开放。
- 侧栏或独立信息板块内的单项字号修复，仅在真实渲染已经出现拥挤、断裂或裁切时允许，而且只能缩小字号，不得放大卡片或文字制造强调。

## 7. 禁止的修改

- 改写用户事实、数字、单位、口径、来源、结论强度或主关系；
- 新增业务判断、行动建议、基准、引语或数据；
- 删除必要来源、合成数据披露、单位、期间、分母或定义；
- 为追求风格而更换不等价图表；
- 添加 eyebrow、装饰色带、标题饰线、空卡片或其他无信息贡献对象；
- 将页面转为整页图片或破坏原生可编辑性；
- 覆盖源 PPTX；
- 在没有明确收益时强制修改。
- 移动、缩放、隐藏或删除非文本数据编码和关系几何。
- 把侧栏注释抽离到主图，导致原区域空洞或页面失衡；
- 单独移动、缩放或放大重复卡片中的某一项，破坏板块的对齐、间距、内边距和字号秩序；
- 源页没有明确可见缺陷时，为制造 before/after 差异而强制修改。

## 8. 工作流

### 阶段 A：基线锁定

记录源 PPTX SHA-256、页数、对象和文本清单，生成基线 PNG 与 layout JSON。

### 阶段 B：编辑诊断

先输出真实渲染中的可见缺陷清单，再输出不超过六行的主诊断。必须包含页面主体、中心结论、表达方法、区域/板块结构、主问题、修改假设和不动内容。诊断只能选择一个主问题；没有明确缺陷时必须选择 `NO_MATERIAL_EDIT`。

### 阶段 C：成组补丁

用 `editorial/scripts/apply_editorial_patch.mjs` 执行有精确目标、预期边界框和理由的补丁。首个候选失败时，只有存在另一个明确且不同的结构假设才允许第二个候选。

### 阶段 D：比较与回归

重新渲染候选并执行：来源保真、数值 token、页数、原生对象、文字底线、越界、信息贡献和 PowerPoint 打开检查。候选没有明显改善或产生任何硬回归时必须回退。

如果源页在编辑前已有与本次操作无关的布局或语义扫描发现，候选可以在“发现集合不新增、不恶化”的条件下继续；不得把基线旧问题伪装成候选通过，也不得要求 Editorial Editor 顺手修复不相关问题。

## 9. 输出

对外交付：一页原生可编辑 PPTX。

内部证据包括基线与候选 PNG/layout、诊断、补丁、补丁审计、验证报告和 manifest，具体见 `references/output-contract.md`。

## 10. 验收标准

### 基础输出

- 一页 16:9 PPTX 可打开；
- 源文件未覆盖；
- 所有交付内容仍为原生可编辑对象；
- 证据文件齐全且哈希对应。

### 需求覆盖

- 六个编辑维度均被诊断；
- 可见缺陷按严重度排序，主问题必须来自最高严重度缺陷；
- 侧栏区域完整性与重复板块内在秩序均有显式判断；
- 修改只服务一个明确编辑假设；
- 禁止项为硬失败；
- 修改后重新执行 OneSlide 原有布局和信息贡献门槛。

### 产品价值

至少三个代表性案例，其中一个由 Case Factory 新建，两个来自既有复杂 OneSlide 页面。至少两个案例发生材料性修改；每个被接受的修改都必须在真实渲染中更清楚，并保持来源、数据和可编辑性。第三方测试 Agent 必须能仅凭模块说明和案例材料完成编辑或正确选择零修改。

## 11. 非目标

- 不编辑多页 deck；
- 不替代 Producer 或 Builder；
- 不做业务内容重写；
- 不建立无限候选或无限美化循环；
- 不把审美分数当作产品价值证明。
